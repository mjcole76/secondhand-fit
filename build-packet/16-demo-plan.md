## Demo requirements from the spec
- Video length between 1 and 3 minutes, publicly visible on YouTube, link supplied on the Devpost submission form (mandatory contest requirement).
- Open on the problem in the first 15 seconds: the genuinely bad flat-lay — crumpled, on a duvet, half in shadow — being rejected with three specific retake instructions. No setup narration first (builder's own past lesson).
- Show the retake passing with a grade and the before/after of the original versus the normalised garment image; this is the differentiating visual.
- Show the buyer path end to end: consent screen, selfie, honest progress state, then the render with the readiness badge and the preview-only label clearly legible on screen.
- Say the name of the sponsor API out loud and show it on screen: Perfect Corp YouCam Apparel Virtual Try-On (mandatory: the video must explain which YouCam API is used).
- Include footage of the project functioning in a real browser on the target device — both desktop and a mobile browser, since the seller flow is phone-first (mandatory).
- Show the /methods page briefly to evidence that thresholds came from real API runs rather than guesswork.
- Use only original or licensed music and avoid third-party trademarks and real marketplace branding; demo listings must use builder-owned or openly licensed garment photos with provenance noted in the repo (mandatory rule on video content and originality).
- Live judge-accessible URL with seeded demo listings, free and unauthenticated, available through the end of the Judging Period; if any render in the demo is precomputed it must be labelled as such on screen (mandatory demo access requirement).
- Screenshots for Devpost: the rejection screen with instructions, the before/after normalisation, the graded listing badge, the render with badge and label, the methods page, the seller insights table.
- Testing instructions in the README and on Devpost covering: which demo listing reproduces the rejection, which reproduces the pass, how to run offline mock mode, and what to expect if the unit budget is exhausted.
- State in the write-up exactly what the product refuses to do (no fit, size, condition or authenticity claims; blocked categories) and list known limitations, including that flatness is a proxy signal and background suppression is conservative by design.
