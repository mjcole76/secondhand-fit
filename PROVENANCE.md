# Provenance and originality

This file is the self-audit of code provenance and asset licensing for Secondhand Fit, kept for the
contest rule:

> The Submission must be the Entrant's original work, solely owned by the Entrant, and must not
> violate the intellectual property or other rights (copyright, trademark, patent, contract,
> privacy) of any other person or entity.
> — YouCam API Skin AI & eCommerce VTO Hackathon, official rules

It records where every file that ships in the submission came from, which third-party software and
services the project relies on and under what terms, and what must be recorded before anything new
is added. It is a factual inventory. The ownership statement itself can only be made by the entrant
and is in [Entrant confirmation](#entrant-confirmation) at the end, which is **not yet signed**.

- Last audited: 2026-09-30 (licence entries updated 2026-10-01; source, asset and dependency
  registers brought up to date with normalisation, consent and buyer photo capture on 2026-10-01)
- Audited tree: everything in the repository except `node_modules/`, `.next/` and `.env`
- Method: every file under `app/`, `components/`, `lib/` and `public/` was listed and inspected;
  imports were checked against `package.json`; the tree was searched for vendored code, attribution
  or licence headers, remote fonts, remote stylesheets and hot-linked media; dependency licences
  were read from `package-lock.json`.

Apart from the normalised copy of the retake, these images are the **seeded demo listing set**. They are drawings, not photographs: no real
garment, person, brand, logo or printed artwork is shown, and nothing was taken from a marketplace,
retailer, stock library or image search. The bad flat-lay is refused by the readiness checks and is
never listed; the other three are listed on `/listings` as demo listings, graded at run time by the
same code as a seller's photo. A judge can reproduce the rejection and the passing retake on
`/sell/new` without uploading anything. The same author, licence and register facts are shown in
the product, on `/listings` and on each demo listing's page, from `lib/listings/seeded-set.ts`, and
`GET /api/listings/seeded` returns them with the grades.

There are currently **no photographs, no fonts, no icon sets, no audio and no video** in the
repository. Typography uses system font stacks only (`app/globals.css`); nothing is loaded from a
font or asset CDN.

Images that users upload at runtime (garment photos and buyer photos) are not part of the
repository or the submission. The server holds them in memory for the try-on request, sends them to
the YouCam API in live mode, and never writes them to disk or to the repository. The seller
readiness check reads the garment photo in the browser; only a small analysis grid (at most 160
pixels on its longer side) is posted to this app's own server, which scores it and keeps the scores
but not the pixels. Once the photo is accepted, the photo itself is posted for normalisation, and
the server keeps the original and the normalised copy in memory against the draft listing, re-encoded
without metadata. Nothing in the readiness or normalisation path is sent to the YouCam API. A try-on sends the same
kind of grid for its garment photo, so the server can grade it for the readiness badge; the grade is
kept in the signed render id and the grid is discarded.

A render served to the browser is wrapped by `lib/tryon/burn-in.ts` in an SVG that adds the
preview-only label and the readiness badge as text. The wrapper is generated per request and is not
a file in the repository; it uses system fonts only.

## 6. Before adding anything new

1. **Code** — write it for this project. If a snippet, algorithm implementation or file is taken
   from elsewhere, record the source URL and licence in section 1 and keep the required notice.
2. **Dependencies** — add the package and its licence to section 3. Do not add a dependency whose
   licence forbids use in a publicly shared repository.
3. **Garment photos for the seeded demo listings** — every photo must be either taken by the
   entrant of a garment the entrant owns, or published under an open licence that allows reuse and
   modification (for example CC0 or CC BY). Add one row per file to section 2 with the
   photographer, the source URL, the licence and the date retrieved. Photos copied from resale
   marketplaces, retailer catalogues or image search are not acceptable. Avoid visible brand logos,
   printed artwork and other people's faces; if a garment carries one, pick another garment.
4. **Photos of people (demo selfie, precomputed renders, screenshots, video)** — use only the
   entrant's own likeness or a person who has given written permission, and record that in
   section 2. A render produced by the YouCam API from two inputs is only as clean as its inputs:
   both must already be in the register.
5. **Fonts, icons, music and video material** — record the licence in section 2 before committing
   or publishing. The demo video must not contain third-party trademarks or copyrighted music or
   material without permission.
