# Testing instructions for reviewers — draft

Draft text for the testing instructions on the Devpost form. Last updated 2026-10-01.

These steps were written from the code and the root `README.md`. They have **not** been walked
through on a deployed URL, because the app is not deployed yet. Walk through them exactly as written
before pasting, and replace `NOT SET` with the real URLs. Paste from the next heading to the end of
the file.

## Access

- Working demo: NOT SET
- Code repository: NOT SET
- No account, login or payment is needed. Nothing has to be installed to use the demo.

The home page, `/try` and `/status` show a "Mode" banner that names how the next try-on will be
served: **live** means the render comes from the Perfect Corp. YouCam Apparel Virtual Try-On API;
**precomputed** means an example made in advance is shown and no API call is made; **mock** means
the app is replaying pinned fixtures and spends no API units. (**cached** is named in the banner
but is not in use yet.) The `/status` page also shows the remaining unit budget.

## 1. See a bad flat-lay rejected (no upload needed)

1. Open `/sell/new`.
2. Under **Try a seeded example**, choose **Seeded bad flat-lay** (a creased T-shirt on a checked
   duvet, half in shadow).
3. Expected: the outcome is **Retake needed**, with three retake instructions covering background
   separation, flatness and occlusion/shadow, and a score for each of the four checks. No API unit
   is spent.

## 2. See the retake accepted (no upload needed)

1. Still on `/sell/new`, choose **Seeded retake** (the same T-shirt laid flat on a plain surface in
   even light).
2. Expected: the outcome is **Photo accepted**.

The two seeded examples are drawings generated by the app, not photographs.

## 3. See a refused category

1. On `/sell/new`, choose **Intimates** or **Swimwear** as the category.
2. Expected: the listing is refused with the reason and a link to the scope statement at
   `/methods#scope`. The photo step does not open.

## 4. Run a try-on

1. Open a listing and choose **Try it on**, or open `/try`.
2. Read the consent statement (what is uploaded, where it is sent, how long it is kept, how to
   delete it, what the result is), tick all five parts and choose **I agree — continue to the photo
   step**. No file picker or camera is offered before this. The server records the consent; a
   try-on request from a session without a current consent record for that listing is refused
   with `403 consent_required` and no provider call. **Withdraw consent** deletes the record and
   returns to the statement.
3. Choose a garment image (JPEG, PNG or WebP). For your photo, choose **Take a photo** (opens the
   front camera on a phone) or **Choose a photo**. Use a photo of yourself or of someone who has
   agreed to it. The photo is checked on the device first (large enough, evenly lit, something in
   the middle of the frame). A photo that fails, such as a very dark one, shows which check failed
   and up to three things to change, and **Run try-on** stays disabled, so no API unit is spent.
   Once the photo passes, choose **Run try-on**.
4. Expected in **live** mode: the progress list marks each stage when it actually happens, with
   the time it happened: checking both images, uploading the garment,
   uploading your photo, task queued, generating, finishing (fetching the render and adding its
   label), preview on screen. The elapsed time and the timeout are shown, and each stage is read
   out by screen readers. The result
   appears under "Source: live YouCam Apparel VTO render" with the label "AI-generated preview only.
   No fit, size, condition or authenticity claim is made." If the render does not finish before the
   timeout, the page says "Render did not finish in time."
5. Expected in **mock** mode: the task runs for about four seconds and returns a placeholder image
   under "Source: mock — offline fixtures, not a live result".
6. In either mode, the result shows a readiness badge ("Try-on readiness: grade A", B or C, with
   the reason) under the label, and the same label and badge are in a band at the bottom of the
   image itself. **Download labelled image** saves the image with that band. **Save to watchlist**
   adds the preview to `/watchlist`, where it is listed with its badge and label.

## 5. If the unit budget or the per-session cap is reached

The demo runs on a fixed budget of YouCam API units, and each browser session can start 5 try-on
renders in any 24 hours (counted with an anonymous cookie). When the budget or the cap is reached,
or the API returns an error, the try-on in step 4 does not fail: it shows a precomputed example
under a banner that begins **"Not a live result"** and says why, with "Source: precomputed example
— not a live result" on the result. When the budget or the cap is the reason, no API call is made.
`/status` shows the budget, the estimated units remaining and how many renders the session has left.

## 6. Run it locally in offline mock mode

Requirements: Node.js 20.9 or newer (sharp needs it), with npm. No API key and no `.env` file are needed.

```bash
git clone <repository-url>
cd secondhand-fit
npm install
npm run dev               # http://localhost:3000
```

With no credentials the app runs in mock mode and makes no outbound request. Steps 1 to 4 above work
the same way. To run against the live API, see "Live mode" in the repository `README.md`.

## What the app does not do

Secondhand Fit shows an AI-generated preview of appearance only. It makes no statement about fit,
size, condition or authenticity. The try-on handles upper-body garments only.
